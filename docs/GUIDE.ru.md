# Session Vault 1.1

Локальное desktop-приложение Windows для чтения, поиска и навигации по истории Codex. Развивает существующий Session Vault 0.3; архитектура Electron + SQLite и исходный визуальный язык сохранены.

## Запуск

Откройте `SessionVault-1.1.0-Windows/Session Vault.exe`. Сохраняйте всю папку сборки вместе: один EXE отдельно не работает. Node.js, Python, API-ключи и аккаунт не требуются. Перед запуском закройте старую версию. Portable означает запуск без установщика; пользовательские данные хранятся в `%APPDATA%\session-vault`, а не рядом с EXE.

В приветствии выберите стандартную папку `%USERPROFILE%\.codex\sessions`, другую папку или один/несколько JSONL. До выбора источника сканирование не начинается. Отмена системного выбора оставляет приветствие открытым; «Позже», крестик и Esc закрывают его. «Больше не показывать» сохраняет настройку. Вернуть приветствие можно в Settings.

Язык по умолчанию — **EN**. В приветствии и Settings доступны **EN / RU / UA** (код украинской локали `uk`). Выбор сохраняется; текст сессий никогда не переводится. Встроенная справка **? / F1** объясняет режимы, служебные сессии, источники и ограничения.

## Ежедневная работа

- **Conversation:** пользователь и ассистент; соседние кнопки с иконками переключают простой диалог, все записи и инструменты. Страницы по 60 записей; длинный текст раскрывается отдельно. Поддерживается безопасное подмножество Markdown: абзацы, заголовки, выделение, код. HTML из сессии не выполняется.
- **Overview:** сводка проекта, сессии, активность, инструменты, упомянутые файлы. Область: текущая сессия, проект (одинаковый cwd) или всё хранилище.
- **Chapters:** автоматические главы по дням UTC с фрагментами переписки и экспортом периода; прежнее оглавление одной сессии доступно отдельно.
- **Timeline:** список событий, горизонтальная шкала, дорожки по типам, Git-inspired история ветвлений и календарь активности. Связи fork/subagent/parent берутся из метаданных; отсутствующие родители обозначены явно. Слияния Git не выдумываются.
- **Topic graph:** карта сессий, предполагаемых решений/задач, упомянутых файлов и частотных слов. Связи означают включение/упоминание/записанного родителя. Три раскладки, масштаб и инспектор источника; прежний частотный граф сохранён.
- **Decisions & tasks:** автоматические кандидаты по локальным правилам EN/RU/UA, с основанием классификации и переходом к оригиналу. Это не AI-резюме и не доказательство выполнения задачи.
- **Search:** SQLite FTS5, Unicode/кириллица и префиксы слов. Все введённые термины должны совпасть. Первые 100 результатов; для остальных уточните запрос. Обрабатываются первые 1000 символов и 12 терминов.
- **Export:** Markdown разговора, нормализованный JSON индекса, либо побайтовая копия исходного JSONL. Native Save As управляет именем и подтверждением замены существующего файла. Отмена, подготовка, успех и ошибка отображаются в приложении.

Режимы находятся в левой панели; глобальный поиск — в верхней строке. Поиск, экспорт, настройки и справка имеют «Назад» / крестик / Esc. Возврат из результата поиска восстанавливает запрос и прежнюю страницу/прокрутку. Состояние текущего представления сохраняется при закрытии. История кнопки «Назад» действует в пределах запуска.

**Клавиши:** `Ctrl+K` — поиск; `Alt+1…5` — представления; `Esc` — назад из служебного экрана/перехода; `Ctrl+B` — левая панель; `Ctrl+Shift+B` — правая; `F1` — справка. Кнопки панелей находятся у соответствующих краёв окна. Настройки панелей, темы, языка и размер/максимизация окна сохраняются.

## Источники и хранение

«Добавить» дополняет набор источников. Приветствие / «Заменить источники» заменяет набор. Удаление источника в настройках удаляет только его производные записи из индекса при обновлении, никогда исходник. При отсутствии стандартной папки можно подключить другую папку/JSONL.

Индекс обновляется раз в минуту при открытом приложении. Кнопка обновления принудительно перечитывает источники, включая заменённые файлы прежнего размера. Строка состояния показывает файл, этап и прогресс; ошибки источников доступны в настройках. Изменяющийся во время чтения файл откладывается до следующего обновления.

Удалённый или временно недоступный исходник помечается; уже созданный кэш остаётся читаемым. Возвращённый файл вновь становится доступен. «Показать исходник» открывает Проводник. Реальный путь файла/папки можно посмотреть и скопировать в правой панели, пути подключённых источников — в настройках.

Данные приложения: `vault-v1.sqlite` (+ WAL/SHM), `sources.json`, `window.json` и Electron Local Storage в `%APPDATA%\session-vault`. **Rebuild index** сохраняет старые SQLite-файлы с суффиксом `.backup-…` и строит новый индекс. Записи недоступных исходников в новый индекс не попадут; резервные копии автоматически не удаляются. Это также путь восстановления повреждённого кэша. При обновлении с 0.3 доступные источники однократно переиндексируются.

## Оформление

System / Light / Dark, отдельная палитра для светлого и тёмного режима. System следует Windows. Каталог из 28 семейств / 43 вариантов адаптирован из палитр установленного Codex Desktop; это фиксированный каталог, без синхронизации с Codex. Проверен контраст основного и второстепенного текста относительно основной поверхности. Сохранены структура developer-tool, разделённые панели, компактная навигация, моноширинные технические подписи и акцентные состояния.

## Границы безопасности и формата

Исходники открываются только на чтение. Приложение не отправляет историю по сети, не имеет сервера, телеметрии и обновления по сети. Renderer работает с `sandbox`, `contextIsolation`, без Node.js; IPC ограничен набором операций и проверкой отправителя. Сетевые HTTP(S)/WS(S)-запросы, внешняя навигация, новые окна, webview и разрешения блокируются. Удалённые изображения/ссылки не загружаются.

Экспорт запрещён поверх подключённых исходников, внутри подключённых папок, каталога приложения и пользовательских данных. Ссылки и файлы с несколькими hard links не принимаются как назначение. Запись готовится во временном соседнем файле. Нормализованный JSON/Markdown экспортируется потоком; исходный JSONL копируется отдельно, не из индекса. Для создания нового экспорта используется hard link: выбирайте локальный NTFS-каталог; на файловых системах без hard links операция вернёт ошибку, не повредит исходник.

Повреждённые JSON-строки, неожиданные JSON-типы и неизвестные события не останавливают чтение остальных записей. Ограничения индекса: 8 MiB на сырую строку; 200 000 символов на запись; около 64 Mi символов и 250 000 кандидатов записей на сессию. Превышение видно в инспекторе. Оригинал остаётся полным. Изображения/бинарные вложения не декодируются, скрытые reasoning-данные не индексируются. Поиск и производные экспорты охватывают только индексированный текст.

## Разработка и проверка

Windows x64, Node.js 24+ с `node:sqlite`, Electron 44.3.0:

```powershell
npm install
npm test
npm start
npm run smoke
npm run package
```

Вместо установленного Electron для упаковки можно задать `ELECTRON_RUNTIME` — путь к распакованному официальному Windows x64 runtime. Сборка отказывается перезаписывать существующий каталог версии. Smoke запускайте с отдельным `SESSION_VAULT_DATA`, чтобы тестовые источники не заменяли ваши настройки. `SESSION_VAULT_SMOKE` позволяет передать внешний тестовый harness готовой сборке; тесты в поставку не входят. Подробные результаты и команды — в `VALIDATION.md`, устройство — в `ARCHITECTURE.md`, краткий итог — в `PROJECT_STATUS.md`.

## Ограничения выпуска

Windows x64 portable без установщика и подписи; проверен на текущей Windows-машине, отдельная проверка Windows 10 не проводилась. Новые схемы Codex могут требовать обновления parser. Нет полноформатного Markdown, предпросмотра медиа, редактирования истории, semantic/AI summaries, embeddings, Chat/Work-импорта, облака, аккаунтов или серверной части. Это сознательная граница 1.1, а не скрытые обещания интерфейса.

## Автоматическая история и ручные отметки

По умолчанию всё строится автоматически из локального индекса. В Settings включите **Manual annotations / Ручные отметки**, если хотите корректировать тип события и добавлять заметку через инспектор. Можно вернуть автоматическую классификацию. Отключение редактирования сохраняет уже сделанные отметки. Они хранятся отдельно в `annotations.sqlite`, переживают пересоздание индекса и не переносятся автоматически на изменившийся текст.

Закрепление и архивирование сессий меняют только списки Session Vault. Фильтр списка позволяет показать архив; исходные файлы не перемещаются. В диалоге доступны копирование текста/ссылки, инспектор пары вызов–результат и построчное сравнение двух записей. Ссылку `session-vault://record/...` открывают внутри приложения через Ctrl+L (системный обработчик протокола не устанавливается). Ctrl+P открывает команды. Ширину панелей можно менять мышью или стрелками на разделителе.

Экспорт периода MD/JSON учитывает область и фильтры, включает источник и основание/ручную заметку. Это отдельное действие от экспорта полной сессии. Анализ ограничен 200 000 просмотренных индексированных записей и 6000 показанных событий; текст события — первые 4000 символов. Большую область сужайте датами/сессией. Карта ограничена 80 сессиями, 100 распознанными событиями, 30 файлами и 18 словами; ветвления — 250 сессиями, календарь — 1096 днями. Ограничения видны в интерфейсе. Полная доступная индексированная запись открывается через инспектор/диалог.

Упоминание файла не означает его изменение; распознанный патч не подтверждает Git-коммит. Главы по дням не являются интеллектуальным выделением фаз проекта. Автоматические метки могут пропускать события или ошибаться — для уточнений предусмотрены ручные отметки.

## Изменения интерфейса после сборки 1.1

В исходниках увеличен текст диалога (15 px), кода (13 px), названий и метаданных; сокращены отступы и ширина области линий ветвлений. В **Настройки → Оформление → Цветовая индикация** доступны «Сдержанная» и «По типам событий». Во втором режиме цвет выделяет типы событий, узлы графа и счётчики; легенда находится рядом с настройкой. Режим сохраняется и следует светлой/тёмной палитре. Цвет не означает, что предполагаемое решение или результат подтверждены.

Эти изменения доступны в исходниках; ранее созданные EXE/ZIP не обновлялись. Дальнейшую сборку выполняет пользователь. AI-функции, физика/мини-карта графа, дополнительные панели разговоров и прочие ранее перечисленные расширения исключены из текущего плана.

## Горизонтальная шкала и дорожки

Шкала идёт слева направо по времени UTC. «Горизонтально» объединяет все типы, «Дорожки» разделяют их по строкам. Близкие события автоматически собираются в карточку со счётчиком. Нажмите её: ниже появится список (40 записей на страницу). Выбор записи открывает инспектор, «Открыть исходное сообщение» — диалог. «Закрыть список» возвращает фокус к группе. Одиночная карточка сразу открывает инспектор. Кнопки масштаба меняют временную группировку и ширину шкалы, не размер текста; «Уместить» подгоняет ширину. При увеличении используйте горизонтальную прокрутку. Все датированные события, возвращённые текущим ограниченным анализом, включаются в группы; прежнее дополнительное ограничение 250 меток на дорожку убрано.
